Start here

Two things before lesson 0001. First, the anchor repo: anchor/vendor-eval-gateway/ is a small mirror of your CloudSufi platform — FastAPI, async SQLAlchemy, Postgres, an OpenAI-compatible streaming gateway, a five-stage pipeline. Every lesson instruments that same system, so caching, retries, tracing and queues compound rather than living in forty unrelated snippets. You instrument it; you do not build it.

Second, lessons 0001 and 0002 need nothing installed but uv. From 0003 onward you need Docker Desktop running. That ordering is deliberate — you get two lessons in before any setup friction.

Tier 1 · Weeks 1–2 · built and ready

Caching & latency

Problems you have already hit and worked around. You solved them by instinct; this is the vocabulary and the felt experience. Highest leverage in the whole map.

  1. 0001 Latency Budget Arithmetic

    Build a per-hop budget for one interview turn and find where the 2.1 s goes. No Docker.

  2. 0002 p50 Is a Lie

    Freeze the gateway for 2 s and watch a standard load generator under-report p99 by 13×. No Docker.

  3. 0003 Cache-Aside and Friends

    Cache the retrieval hop, then kill Redis and watch the service degrade to slow rather than down.

  4. 0004 Eviction, and Why LRU Is Wrong

    Fill Redis until writes fail, then watch a batch sweep flush your hot set under LRU but not LFU.

  5. 0005 Stampede, Penetration, Avalanche

    Turn one cache miss into 200 upstream calls, then back into one with single-flight and TTL jitter.

  6. 0006 Redis Is Not Magic

    Lose data on purpose, price each fsync policy on your own disk, and see a fork stall your p99.

Reference sheets

The compressed residue of the lessons, designed to print and be pinned up. These are the documents you will actually return to.

  1. R1 Latency Reference Card

    Orders of magnitude, the LLM-turn scale, percentile arithmetic, budget rules of thumb.

  2. R2 Caching Decision Tree

    Should this be cached, which strategy, key design, the three failure modes, eviction, persistence.

  3. R3 Resilience Patterns Card

    Six controls and what each one bounds, the retry arithmetic, every threshold and what it is derived from, what to shed first, the idempotency checklist.

  4. R4 Interview Probes

    Every probe from every built lesson with a model answer — 107 so far. Generated from the lessons, so it cannot drift. Use it out loud: answer first, reveal second.

Tier 1 continued · built and ready

Streaming, LLM caching, resilience, Postgres

The rest of the tier, built in batches of two to five so the pitch could be corrected between them. Each lesson opens with the line on your résumé it defends, and links the chapter in Résumé Mastery that defends it from the other side. Tier 1 is complete; numbering from Tier 2 on is indicative — see NOTES.md.

  1. 0007 SSE vs WebSocket for Tokens

    Read your own tokens as bytes, then find the one line that is the difference between a 390 ms first word and a 3.8 s one.

  2. 0008 KV Cache and Prefix Caching

    Compute how many conversations fit on one card, then find the one-word prompt edit that costs 8× your first word.

  3. 0009 Cache-Aware Routing

    Take prefix-cache hit rate from 47 % to 78 % across four replicas — then find the router that puts everything on one.

  4. 0010 Backoff with Jitter

    Reproduce the famous 243× exactly, find your pipeline produces 3× instead — then measure what jitter costs you in completed runs.

  5. 0011 The Breaker You Have to Defend

    Break a breaker twice: one failed call refusing 100 healthy requests, and a dependency too slow for it to notice.

  6. 0012 Timeout Budgets and Deadline Propagation

    Blow an 8 s budget by 48 % with every timeout honoured, then cap it exactly — and count what the cap costs.

  7. 0013 Admit, Queue, or Shed

    Collapse goodput to 44 % with every upstream call succeeding, then bound the queue and find it buys the tail rather than the throughput.

  8. 0014 Idempotency Is a Key and a Clock

    Apply one request sixteen times out of sixteen with no error raised, then once — and find the failure no unique index can catch.

  9. 0015 The Wait No Timeout Can See

    Take request p99 from 1 947 ms to 112 without touching a query — then break your driver with a proxy, twice.

  10. 0016 The Update That Was Never Refused

    Lose seven of eight updates with no error raised, then find the retry budget that silently drops eight more.

  11. 0017 The Await Inside the Transaction

    One line's indentation takes throughput from 5.5 turns a second to 0.9, and blows the budget on 17 of 24.

  12. 0018 Lock, Retry, or Don't Read

    Optimistic never beat pessimistic at any contention level — and the strategy nobody offers beat both by 12×.

  13. 0019 The Snapshot Nobody Closed

    One idle session under asyncpg kept 499 900 dead rows from vacuum, and the plan never changed — only the buffers did.

  14. 0020 The Read That Beat Its Own Write

    A replica 0.2 ms behind missed 493 of 500 reads from a fast client and none from the ORM. Then the token that fixes it.

Tier 2 · Weeks 3–4 · being built

Async messaging — the real hole

Nothing on your résumé is asynchronous. This is the tier that changes the shape of what you can be trusted to design, and the tier where the five-stage pipeline stops being a function call. The queue-shapes lesson moved forward to 0022 and became the choice between a table and a broker, so the two Kafka lessons now follow it rather than precede it.

  1. 0021 Stuck or Twice

    A frozen worker kept its lock for the whole pause, and every mechanism that stopped waiting did the job twice. Then the key that makes it once.

  2. 0022 A Table Before a Broker

    No order of two writes survived a broker stall and a kill; one transaction lost nothing. Then the three break points that do send you to a broker.

  3. 0023Kafka in Anger

    Produce and consume, find the log on disk, and see partitions as the only unit of parallelism you get.

    Résumé void: your skills lines name no messaging system at all.

  4. 0024How Kafka Loses Your Data

    Misconfigure acks and min.insync.replicas, kill a broker, lose a message, then fix the five knobs.

    Interview probe: which five knobs decide it, and what did you set them to.

  5. 0025Orchestration vs Choreography

    Rewrite the five-stage pipeline both ways, then say out loud which failure each shape makes cheaper.

    You already did this: the ADK schematization pipeline is orchestrated, and you should know why.

  6. 0026Saga and Compensating Actions

    Have stage 4's validation gate reject, then unwind stages 1 to 3 instead of abandoning the run.

    Gap in what you built: today nothing unwinds — fine until a stage has an external side effect.

  7. 0027The Outbox Pattern and CDC

    Write to Postgres and publish an event without a distributed transaction, then read the change stream.

    Anchored to: SAP BW to BigQuery — lineage is a change stream you built by hand.

  8. 0028Event-Source Your Thought Traces

    Promote agent thought-traces from an MLflow side effect to a first-class, replayable event log.

    You already half-did this: traces exist; they are just not the source of truth.

Tier 3 · Weeks 5–6 · not yet built

Distributed systems core

The vocabulary tier. Less code, more naming things correctly — which is most of what a senior design interview actually tests.

  1. 0029Consistency Guarantees, Honestly

    State what CAP actually forbids, then fix 0020's stale read by naming the guarantee you needed.

    Interview probe: most candidates cite CAP wrongly; naming read-your-writes is the senior answer.

  2. 0030Partitioning: Rings and Shard Keys

    Build a hash ring in 40 lines and measure key movement, then pick a shard key and find where it skews.

    Anchored to: vector-store shard routing, and the eval-results table you would have to split.

  3. 0031RAG Retrieval as a System

    Trade recall against latency across index types, then measure what a wrong k costs the answer.

    You already did this twice: on-device RAG over quantized MobileLLM, and the Scout pass.

  4. 0032Locks and Liveness

    Have two workers claim one task, then break a naive Redis lock and fix it with a fencing token.

    Anchored to: claiming datasets off a work queue across replicas.

  5. 0033The Scalability and HA Ladder

    Order every scaling move by cost, then compute a real availability budget from your own dependencies.

    Capstone: synthesises Tiers 1 to 3 into the answer to "so how would you scale it".

Tier 4 · ongoing · not yet built

Production ownership

The tier that produces résumé lines you do not currently have: observability, IaC and auth. Tracing first, because it pays for itself the day you turn it on.

  1. 0034Tracing a Five-Stage Pipeline

    One OpenTelemetry trace spanning all five stages, so 0001's budget table stops being a guess.

    Highest value in the tier: it turns every latency claim you make into a measurement.

  2. 0035Metrics and Logs at Volume

    Scrape the gateway, choose push or pull on principle, and write logs that survive being searched.

    You already did this: structlog everywhere, and no metrics endpoint anywhere.

  3. 0036Kubernetes Below kubectl apply

    Service types, probes and the sidecar pattern, mapped onto the gateway you already run on GKE.

    You already did this: deployed to GKE, without owning what is underneath.

  4. 0037Terraform from Zero

    Stand this whole lab up from code, externalise config, and kill the last hardcoded secret.

    Résumé void: no IaC appears anywhere on your CV. This is the cheapest line to earn.

  5. 0038Shipping a Prompt Safely

    Canary a prompt and a model version, pin sessions to it, and drain them without dropping a turn.

    You already did this: a prompt change is a deploy, and you shipped many.

  6. 0039The Eval Harness as a Regression Gate

    Wire offline evals into a gate that blocks a bad prompt, and size the sample so the gate is not noise.

    You already did this: 100+ offline evals, and the 4.6% to 30.7% lift you have to defend.

  7. 0040JWT, Sessions, OAuth — Once and For All

    The whole auth family in one sitting, then forge a token against a deliberately wrong verifier.

    Résumé void: no auth appears anywhere on your CV. See NOTES.md on ordering this earlier.

  8. 0041Multi-Tenant RBAC

    Build the permission model that decides which vendor sees which rubric score, then try to escape it.

    Anchored to: a vendor-evaluation platform is multi-tenant by definition.

  9. 0042Sensitive Data Boundaries

    Draw the redaction and tokenization boundary, then find what your prompts and logs currently leak.

    Live risk in your stack: vendor documents go into a third-party model, and traces persist.

  10. 0043Your Gateway Is an API Gateway

    Name the architecture you reinvented, fix round-robin to least-outstanding, and correct your paging and 429s.

    You already did this: you built an API gateway without calling it one. This lesson gives it its name.
