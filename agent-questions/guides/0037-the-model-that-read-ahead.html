Agent question 37 · extra · Day 65 · about 10 minutes

The model that read ahead

Original: Advanced NLP Interview #11 · The Causal Mask Leak

1The question

“Training loss on a next-token model has dropped far below anything plausible, and everything it generates is nonsense. What in attention do you suspect first? Then: how can masking with −inf, or with a large negative number instead, still break in 16-bit arithmetic?” Senior ML Engineer interview, Google

This builds on Day 64's nanoGPT: CausalSelfAttention scores every token against every other, and a causal mask (Day 57: −∞ above the diagonal before the softmax) stops a token seeing the ones after it. Guide 24 explains loss and held-out sets.

2The trap

Trap A: “Low loss is good news. Generation must be a sampling problem: lower the temperature.”

Trap B: “Validation loss is just as low, so it isn't overfitting. The model is simply good.”

A trusts a number that is too good. B trusts a check that runs through the same broken forward pass.

3Your 30-second answer

“Loss that low with garbage output means the model saw its targets in training. Every position trains at once, and only the causal mask stops position t reading token t+1. I trained a tiny character model twice, changing only that flag: masked, validation loss about 2; unmasked, 0.04, and it wrote one letter over and over. The tell is per position: near zero everywhere except the last position of each block, the only one with nothing to its right to copy.

Then I'd find where the mask is built, including boolean masks moved between PyTorch functions that read True oppositely. The second trap is a row with no allowed key, such as a filler position padding a short text: −inf makes its softmax NaN, a big finite number spreads its weight over hidden tokens, and in fp16 −1e9 becomes −inf anyway (bf16 keeps float32's range).”

4The idea in plain words

A trainee weather forecaster practises on old records: for each past day, predict the next day's weather. Her scores are perfect. Then you notice each archive box also holds the next day's newspaper, weather page on top. On her first real Monday there is no Tuesday paper, and she guesses wildly.

Training a next-token model is that practice. Day 64's forward with targets predicts every position in one pass, so token t+1 sits right beside the position that must predict it. The causal mask takes the newspaper out of the box: scores for later tokens become −∞, so after the softmax their weight is exactly zero.

Without the mask, the model learns the easiest job there is: copy the next token. Day 64's generate has no next token to copy, so it falls apart.

Think about it. In our leaky run (below) the validation loss was low too. Why didn't the held-out text catch the leak? It's scored by the same forward pass, so each validation position could read its own target just as training positions did (our reasoning).

5How it works: read the losses, find the mask, check the empty rows

An illustration, from our own run. The same tiny transformer twice on Karpathy's tiny-Shakespeare text (65 characters): 3 layers, 4 heads, width 128, blocks of 64 characters, 600 steps of AdamW (a variant of Adam) at learning rate 0.001, PyTorch 2.15 on a laptop CPU. The only difference is is_causal.

  1. Read the loss position by position. With the mask off, every position scored about 0.003 except the last in each block, at 2.56: its target lies outside the block, so it must really predict. The average is close to 2.56 ÷ 64 = 0.04 (our arithmetic). For scale, nanoGPT's README reports a best validation loss of 1.4697 for its larger character model. A loss of 0.04 on this data says each position can see its own answer.
  2. Find where the mask is built. nanoGPT has two paths: scaled_dot_product_attention(..., is_causal=True) with attn_mask=None, and a manual one that builds a lower triangle with torch.tril and fills the zeros with float('-inf'). A wrong triangle or a dropped flag leaks. So can moving a boolean mask between PyTorch functions: for scaled_dot_product_attention, “a value of True indicates that the element should take part in attention”, while for nn.MultiheadAttention “a True value indicates that the corresponding position is not allowed to attend”. When we passed the same lower-triangle mask to the second, position 0 attended only to positions 1 and 2, the future.
  3. Confirm the fix with one edit. Change only the last input token, rerun the forward pass, and compare the outputs at every earlier position. A correct mask leaves them identical. In our run the biggest change was 0 with the mask and 0.0136 without it.
  4. Check rows with no allowed key. Batched texts of different lengths are padded with filler tokens, and the filler is masked out. With the filler on the left, a filler position's causal row may see only filler: in our six-position example with two filler tokens, rows 0 and 1 had no allowed key. Our runs in PyTorch 2.15 on CPU:
    • scores 1, 2 and two hidden at −1e9: weights 0.27, 0.73, 0, 0, so any large negative works while one key is allowed;
    • an empty row through a hand-written softmax with −inf: NaN (“not a number”) in every entry, which then spreads through the backward pass;
    • the same row with −1e9: weight 1/6 on each of the six positions, four of them real tokens that come later, with no error;
    • the same boolean mask passed to scaled_dot_product_attention: zeros for the empty rows. That's this version on this backend; test yours (our caution).
    In fp16, the 16-bit half-precision format, the largest magnitude is 65,504, so −1e9 is stored as −inf and the quiet leak becomes the NaN. bf16, the other 16-bit format, keeps float32's range, so there −1e9 stays finite and the leak stays quiet (our run: 1/6 each). No mask value rescues an empty row; it needs a defined output (our reading).

6Follow-ups they'll ask

Couldn't the low loss be validation text that also appears in training?

Overlap would lower the loss at every position alike. A mask leak leaves the last position of each block at a normal loss, because its target is outside the block: in our tiny-Shakespeare run, 2.56 there against 0.003 elsewhere. So the per-position losses tell the two apart (our reasoning).

Why does a NaN in one row matter so much?

Anything multiplied or added with NaN is NaN, so one fully masked row with −inf scores makes that row's softmax output NaN, and the backward pass carries it into the gradients of shared weights. In our PyTorch 2.15 run, softmax over a row of −inf scores returned NaN in every entry.

Isn't −1e9 the safe choice, then?

Only where the format can hold it, and only for rows that keep at least one allowed key: in our PyTorch 2.15 run, scores of 1, 2, −1e9, −1e9 gave weights 0.27, 0.73, 0, 0. A row with no allowed key spreads its weight evenly over keys meant to be hidden. fp16 can't hold −1e9 at all (its largest magnitude is 65,504), so it is stored as −inf; bf16, with float32's range, can.

7Check yourself

Why does a model with a leaking causal mask write nonsense even though its loss is tiny?

In training it learned to copy the next token, which it could see. When generating, the next token doesn't exist yet, so the skill it learned has nothing to work on.

Describe the one-edit test for a causal mask.

Change only the last input token, rerun the forward pass, and check the outputs at every earlier position are unchanged. Any change means some position can see a later token.

A boolean causal mask works with scaled_dot_product_attention but leaks in nn.MultiheadAttention. Why?

The two read True oppositely: in scaled_dot_product_attention True means “may attend”, in nn.MultiheadAttention True means “blocked”. The same mask hides the past and shows the future.
