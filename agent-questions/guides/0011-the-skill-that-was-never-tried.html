The skill that was never tried

Original: AI Agent Engineering Interview #7 · The A Priori Skill Trap

1The question

“To save engineers' time, your PM suggests letting the agent draft its own skills from each task's description. Benchmarks say that can leave the agent worse off. Why? And what should a skill be made from instead?” Senior AI Engineer interview, OpenAI

A skill, from guide 9, is a folder of instructions an agent opens when a task needs it. Here the question is not when it opens, but what's written inside.

2The trap

Trap A: “Today's models aren't good enough. Wait for the next one.”

Trap B: “Then skills don't work. Drop them.”

In the study below, self-written skills scored below no skills with three leading models, while hand-written skills helped a lot on the same setups. So the problem isn't the writer's strength, and it isn't skills. It's what the skill was written from.

3Your 30-second answer

“A skill written from the task description can only hold what the model already believed. Nothing in it was tried. At best it adds nothing. In one benchmark it did worse than no skill on all three setups tested: the skills often went unused, writing them ate the run, and when used, their confident wrong steps got followed. I'd build skills from runs that worked: do the task, confirm it with a test, write down what actually worked, and keep the skill only if it beats no skill.”

4The idea in plain words

On her first day, a new hire is asked to write the team's how-to guide for a job she has never done. The guide looks great: neat numbered steps, firm warnings in bold. But every line is a guess.

Worse, next month's new hire trusts it. It's in the official binder, so he follows the steps and stops asking questions. Before the guide existed, he would have tried things, noticed what went wrong and asked.

Now picture a colleague who has done the job twenty times writing down the three surprises that caught her out. Same format, same binder. Completely different value, because every line came from doing the job.

A skill written from the task description is the first guide. It is made only of what the model could already see and already believed. A skill built from the guide 6 trace of a run that worked, the log of every step, is the second. The difference is whether the skill has ever met the real system.

Written from the description
Task description→Model writes SKILL.md→Guesses, in a confident voice
Built from runs
Run the task→A test confirms it worked→Write down what worked
Think about it. A skill written in advance says “search results are always sorted by date.” Without the skill, the agent would look at the results and notice they aren't. With the skill, what does it do? It trusts the file and skips the look. The guess was always in the model; the skill just switched off the checking that used to catch it.

5How it works: building a skill from runs

  1. Run the task first, without a skill, and keep the trace.
  2. Confirm the outcome with something outside the writer: a test, or at least a separate checker. Voyager, a Minecraft agent, stored a program in its skill library only after a self-verification step, a second GPT-4 call reading the game state, confirmed the task was done.
  3. Write down what worked: the steps, plus the surprises the run ran into. Anthropic's skill guide describes this: finish a task with Claude, notice what context you kept supplying, then ask Claude to turn that into a skill.
  4. Prove it with an A/B test: the same tasks with and without the skill. Anthropic's guide says to measure the no-skill baseline first. Keep the skill only if it wins.
  5. Recheck it when the tools or the model change, since what worked may stop working.

Worked example, with real numbers. SkillsBench (latest version, June 2026) tested this directly. In one session the agent wrote skill packs using Anthropic's skill-creator skill; then a fresh agent solved the task with only those packs. It's close to the PM's plan but not identical: the writing agent could look around the task's environment, but was told not to solve the task. Against no skills at all:

SetupSelf-written skills vs no skills
Claude Code + Opus 4.7−8.1 points
Codex + GPT-5.5−11.3 points
Gemini CLI + Gemini 3.1 Pro−11.5 points

Hand-written skills added 18.2 to 24.8 points on the same three setups. The authors audited 12 runs and found the reasons. In 10 of them, the solver never even looked at the generated skills; the authors tie this to the Codex and Gemini CLI setups. In one Claude Code run, writing the skill used up the run before any answer was produced. And when a skill was used, its wrong assumptions were followed: one swapped a careful multi-check routine for a one-shot script whose sanity limits were too loose to flag its own implausible result.

Now the other way. Voyager (2023) built its library only from checked programs and found 3.3× more unique items than the previous best agent. Removing self-verification cut the items it discovered by 73%.

6Follow-ups they'll ask

Isn't Voyager also an agent writing its own skills?

Yes. The difference is what it writes from: code that ran and was checked. Anthropic's guide also has the model write skills, after doing the task. Who writes matters less than what they write from.

What if your runs come from a mediocre agent?

Then the skill records what worked, even if clumsily, which is still real. The A/B test stops anything that doesn't beat having no skill.

What if there's no test to confirm a run?

Use a separate checker, as Voyager did, but treat it as weaker than a test. Add a person's review, or a real outcome such as whether the change was accepted.

7Check yourself

Why can't a skill written from the task description add new information?

Everything in it comes from the description and what the model already believed. Nothing was tried against the real system, so nothing new was learned.

Give the three reasons the SkillsBench audit found for self-written skills hurting.

The solver often never opened them; writing them used up the run; and when used, their confident wrong steps were followed without checking.

What two checks should a skill pass before it ships?

It's built from a run that a test (or a separate checker) confirmed, and it beats no skill in an A/B test on the same tasks.

8Words to know

Self-verification
A separate check, here a second model call, that confirms a task was really done before its program is saved.
A/B test
Running the same tasks two ways, here with and without the skill, and comparing.
