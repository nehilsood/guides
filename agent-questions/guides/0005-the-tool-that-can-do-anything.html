The tool that can do anything

Original: AI Agent Engineering Interview #1 · The Meta-Tool Trap

1The question

“Your agent has 70 REST tools. To compare one phone's price in four countries, it makes 12 tool calls, one after another. When you let it write and run a small program instead, it succeeds more often and takes fewer turns. Then why don't all agents work this way?” Senior AI Engineer interview, Google

Code execution means the model writes a short program and your system runs it, instead of the model asking for one tool at a time. A REST tool wraps one web API endpoint, such as “get price”. Its schema is the JSON definition of the arguments it accepts.

2The trap

Trap A: “Generated code might be buggy. Tool calls are safer.”

Trap B: “No reason. It's a prompt change, so switch every agent over.”

Tool calls have bugs too: a wrong date passes the schema check just fine. The difference is what the model is allowed to do, and what it costs to make that safe.

3Your 30-second answer

“A tool call is one checked action from a fixed menu. A program can do anything the language can. That's why it wins: twelve round trips become one program, and the in-between results stay out of the model's context.

It's also the cost. I can't check a program in advance, so safety has to come from where it runs: a sandbox with hard limits, no open internet and no secrets inside. That's infrastructure someone must build and run, so it isn't the default everywhere. And payments stay separate tools.”

4The idea in plain words

You need a phone's price in four countries, and you have an assistant.

Way one: you phone them twelve times. “Check the US price.” “Now the exchange rate.” Slow, but every request comes from a short list of errands you trust them with.

Way two: you hand over a written plan and your bank card. One trip, much faster. But now they can walk into any shop and buy anything.

Way one is ordinary tool calling, the loop from guide 1: each tool call is checked against its JSON definition, as in guide 2. Way two is code execution. People call code a meta-tool: one tool that can do what all the others do, and more.

Sensible people don't refuse way two. They hand over a prepaid card with a limit, a list of allowed shops and a time to be back by. In software, that is a sandbox: a sealed-off place to run the program, with limits set from outside it.

Tool calls: 12 turns, each checked
Model picks a tool→Schema check→Result back to model↺ 12 times
Code execution: 1 turn, contained
Model writes a program→Runs in a sandbox→Only the answer comes back
Think about it. The model makes a mistake and writes a loop that never ends. With tool calls, the worst is one bad call. With code, the loop keeps going, maybe making thousands of calls, while the model waits. Who stops it? Only something outside the program: a timer it can't switch off.

5How it works: what you build before code is safe

  1. Run it in a sandbox, never on your own server. Cloudflare's Code Mode, where writing code is how the agent uses its tools, runs each snippet in a fresh V8 isolate (a light, sealed box from the V8 JavaScript engine) and throws it away afterwards. An isolate starts in a few milliseconds and uses a few megabytes.
  2. Set hard limits from outside. The limits must belong to the sandbox, not the program, so a runaway loop gets stopped. On Cloudflare's Workers platform, which Code Mode runs on, the runtime caps each isolate at 128 MB of memory and ends code that runs past its CPU-time limit.
  3. Block the internet by default. In Code Mode, the program's own fetch() and connect() calls throw errors. It can reach only the tools it was given.
  4. Keep the keys outside. Code Mode's supervisor holds the access tokens and adds them to each tool request, so the program never sees a key.
  5. Keep irreversible steps as tools. A payment or a delete goes through a declared tool that can ask for approval each time.

Step 3 matters most because of Simon Willison's lethal trifecta: an agent with private data, untrusted content (a web page, an email) and a way to send data out can be tricked into leaking that data. Open internet supplies the third part.

Worked example, with real numbers. The CodeAct paper tested 17 models and found code as the action format gave up to 20% higher success and needed up to 30% fewer actions. Its new test set has 82 tasks that typically need several tools. Anthropic's Code execution with MCP post (Nov 2025; MCP is a standard way to plug tools into agents) takes a meeting transcript from Google Drive and attaches it to a Salesforce record. In code, the transcript goes straight from one tool to the other without passing through the model. Tokens dropped from 150,000 to 2,000, a 98.7% saving. Both sources name the bill. Anthropic says generated code needs a sandbox, resource limits and monitoring, which adds operational overhead. CodeAct's impact statement warns that, at worst, an agent could break out of its sandbox.

6Follow-ups they'll ask

Can't you just check the code before running it?

A scanner helps, but code can reach the same dangerous call in a roundabout way. The limits have to live where it runs.

When would you keep plain tool calls?

One-call tasks, where starting a sandbox costs more than the round trip it saves; actions that need a person's approval each time; and weaker models that write unreliable code.

Why are models better at writing code than calling tools?

Cloudflare's explanation: models have seen huge amounts of real code in training and very few tool calls. Code also lets them loop and keep results in variables.

7Check yourself

Why isn't “code can have bugs” the real reason?

Tool calls can carry wrong values too. The real difference is that a tool call is one checked action from a fixed menu, while a program can do anything the language allows.

Where do the token savings in the Google Drive to Salesforce example come from?

The transcript moves from one tool to the other inside the program, so it never passes through the model's context: 150,000 tokens became 2,000.

Name four things a sandbox setup needs before code execution is safe.

A sealed place to run (a sandbox), hard limits set from outside, no internet except named destinations, and no keys inside.

8Words to know

Code execution
The model writes a program and your system runs it, instead of one tool call per turn.
Sandbox
A sealed place to run untrusted code, with limits the code can't change.
Lethal trifecta
Private data, untrusted content and a way to send data out, all in one agent.
