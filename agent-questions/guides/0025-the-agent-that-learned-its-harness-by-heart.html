The agent that learned its harness by heart

Original: AI Agent Engineering Interview #18 · The Harness Overfitting Trap

1The question

“We fine-tuned an agent on 50,000 recorded runs, every one collected in a single harness. A customer runs that model inside another harness, on tasks of the same type, and its scores fall off a cliff. Nothing about the weights or the task changed. So what did the model really learn?” Senior AI Engineer interview, Google DeepMind

The harness (also called a scaffold) is the code around the model: tools, prompts, and how results come back (guide 1). A recorded run is a trajectory. Fine-tuning takes a trained model and trains it further on examples; here, supervised fine-tuning (SFT) lowers the model's loss on every token the recorded agent wrote, so it learns to write the same. A model's weights are the numbers it learned in training; the base model is the model before this extra training. “32B” means 32 billion weights.

2The trap

Trap A: “The customer's harness has a different prompt. Tweak it and the model will be fine.”

Trap B: “Collect more trajectories.” From the same harness, that teaches the same habits harder.

Both treat it as a setup slip. The cause went in during training.

3Your 30-second answer

“It learned the task wrapped in that harness's habits, and it can't tell them apart. Fine-tuning makes the model copy every token in the recorded runs: the tool-call format, the tool names, how results look, the rhythm of planning. Nothing marks which tokens are the task. In a new harness its first call may not even parse, and each mistake leads somewhere stranger.

That's been measured: a model trained only in OpenHands scored 52.6% on SWE-bench Verified there, as its developers reported, and 8.4% in OpenCode, which couldn't parse its tool calls. Its base model varied far less. I'd check the base model in both harnesses and read where failed runs first go wrong. The fix is in the data: varied tool formats and harnesses, and a held-out harness in every evaluation.”

4The idea in plain words

A new cashier trains for three months on one supermarket's till. She learns the job: scan, weigh, take payment. She also learns that till: where the buttons are, the code for bananas, which screen comes next.

She moves to a shop with a different till. The job hasn't changed, but her hands go to buttons that aren't there and she types the old banana code. An error screen she's never seen appears, she presses what usually fixes things, and the next screen is stranger still. She doesn't get a bit slower; the queue reaches the door.

Fine-tuning on one harness is those three months: the model learns the task and the harness's dialect together, because every example had both.

Training harness: every step looks familiar
Task→Call in the trained format→Familiar result↺
New harness: off the map from step one
Task→Call the parser can't read→Unfamiliar error→Stranger next step
Think about it. In every training example, the line that fixed the bug sat inside the same brackets and tool name. During training, what told the model that the brackets didn't matter?

5How it works: what it learned, and how to tell

  1. Format is learned first. In Agent-FLAN (Chen et al., 2024), training on agent data in fixed formats (ReAct, which writes a thought, then an action, then reads the result; and JSON), loss on the formatted data fell fast, to 0.04, while what they call content loss stayed at 0.54, and the authors write that “the model quickly gets overfitted to the format itself”.
  2. The collapse has been measured. DCAS (Thangarajah et al., ASE 2026) ran open coding models in four harnesses. SWE-Lego-Qwen3-32B, trained in OpenHands, fell to 8.4% in OpenCode because “its tool-call output format is incompatible with OpenCode’s parser” (the parser from guide 2), leaving most runs with no readable actions.
  3. Training put it there. The untrained base models varied less across harnesses than any fine-tuned one, so the authors conclude the gap is “something installed by training”. The Qwen3-Coder-Next report (March 2026) agrees: “Models trained on trajectories from one scaffold do not transfer strongly to others.”
  4. Why a cliff, not a slope. My reasoning: it trained only on good histories from one harness. One unfamiliar step puts it somewhere new, its next step is worse, and errors compound as in guide 1.
  5. Diagnose before fixing. My suggestions: run the base model in both harnesses to see how much of the gap the fine-tune added, and read the first wrong step in 50 failed runs. Rejected calls or missing tool names in the first few steps point to dialect; a wrong plan later points to the task.
  6. Then fix the data. Qwen found that training with more tool-call templates raised its SWE-bench Verified score with data volume kept the same. AgentTuning (Zeng et al., 2023) found that its 7B model trained on agent data alone scored 0.09 on unseen tasks, against 0.67 when that data was mixed with general data.

Worked example, with real numbers. DCAS's SWE-bench Verified pass rates, same tasks, four harnesses (the 52.6 is the developers' own reported score):

6Follow-ups they'll ask

Can't a better system prompt in the new harness fix it?

Not reliably. My reasoning: a prompt changes what the model reads, not the habits training put into its weights; in the DCAS study, SWE-Lego-Qwen3-32B kept writing tool calls OpenCode's parser couldn't read. A quick stopgap is an adapter that translates between the two formats; the real fix is training data in many formats.

Won't training on many harnesses solve it?

It helps, but the DCAS study says it isn't enough alone. Qwen3-32B-Nex-N1, trained on varied multi-format runs, still scored 26.2% in OpenCode and 15.6% in mini-swe-agent, against 50.5% reported in OpenHands. The authors argue models also learn each harness's planning conventions, and planning-aware training helped on harnesses the model never saw.

How would you report the model's score honestly?

Name the harness, and add at least one harness the model never trained in, plus the base model's spread. The DCAS authors call a SWE-bench score “methodologically incomplete without specifying the scaffold”.

7Check yourself

What does supervised fine-tuning on agent trajectories actually train the model to do?

Write every token the recorded agent wrote, given what came before: the reasoning and the fix, but equally the tool-call format, tool names and other harness habits. Nothing in the training marks which tokens are the task.

Why did the DCAS study conclude that the cross-harness gap was installed by training?

Untrained base models varied less across the four harnesses than any fine-tuned model. Qwen3-32B base spanned 29.0 to 8.0 (21 points); SWE-Lego-Qwen3-32B, fine-tuned in OpenHands, spanned 52.6 (its developers' reported score) to 8.4 (44.2 points).

What did Agent-FLAN observe about format and content during agent fine-tuning?

Loss on the formatted data fell fast, to 0.04, while what they call content loss stayed at 0.54 (their Figure 2), so the model learned the fixed format (ReAct, JSON) first; the authors say it “quickly gets overfitted to the format itself”.

8Words to know

Supervised fine-tuning (SFT)
Further training on examples so the model writes what the examples wrote.
Scaffold
Another word for the harness around the model.
Format overfitting
Learning the training data's surface format so well that other formats fail.
Held-out harness
A harness kept out of training and used only to test.
