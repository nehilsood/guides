Agent question 32 · extra · Day 36 · about 10 minutes

The score that only went down

Original: AI Agent Engineering Interview #38 · The Goodhart Machine Trap

1The question

“You leave an agent alone overnight. Every five minutes it edits the training code, trains a fresh model, and keeps the edit only if validation loss beats its best so far. By morning it has done 100 rounds and the kept loss has fallen steadily. What do you check before you trust the winner?” Senior ML Engineer interview, Google DeepMind

This builds on Day 35: tune on validation scores, score the test set once at the end, and call a gap smaller than the spread a tie. The setup matches Karpathy's autoresearch (March 2026): 5-minute runs, about 100 a night, scored in bits per byte (guide 24).

2The trap

Trap A: “It fell for 100 rounds, so the model got better. Ship the last kept version.”

Trap B: “The model never trained on the validation set, so it can't be overfit to it.”

A keep-only-if-better loop draws a falling line whatever the edits did, and choosing by a score is itself a kind of fitting.

3Your 30-second answer

“The falling line proves little: the loop keeps an edit only when it beats the best so far, so the kept score can't go up. I check four things.

First the scorer: could the agent touch the evaluation code or the validation data? Then noise: I re-run the baseline and the winner with a few random seeds, the numbers that fix a run's randomness, and count a gain only if it beats the spread. Then selection: 100 choices made on one validation set fit it a little, so I score the winner once on unseen test data. Last the budget: it won at five minutes, so I retrain it at full length. In Dwork et al.'s experiment, a reused held-out set reported over 63% accuracy on coin-flip labels.”

4The idea in plain words

A baker enters the same village contest every Saturday, judged by the same three neighbours. Each week she changes one thing; if the score beats her record she keeps it, otherwise she goes back. Her record creeps up.

Some changes helped. Some weeks the oven ran hot and a lucky cake set an unrepeatable record. Many suit three cinnamon-loving neighbours, not cake eaters in general. The judges taste it warm; guests eat it a day later. And she writes the scores down herself.

Choosing by a score slowly fits the scorer. That's adaptive overfitting: each result steers what is tried next, so the score drifts from how the model does on new data. Keeping the best of many noisy tries is often called the winner's curse: the top score is partly luck, so a repeat comes in lower.

One round of the overnight loop
Edit the training code→Train 5 minutes→Score on validation→Beat the best? Keep : undo↺ 100 times
Think about it. A do-nothing edit still scores a little higher or lower each run, by chance. Try 100 of them: how good does the best look? For a bell-shaped spread, the best of 100 lands about 2.5 standard deviations better than average (our arithmetic). The loop keeps it.

5How it works: four checks, cheapest first

  1. Is it still the same score? In autoresearch the data split and the scoring function sit in prepare.py, which the agent's instructions call read-only. Our reading: a rule in a prompt doesn't block a write. Our numbers: two batches with loss 1.0 over 1,000 tokens and 3.0 over 10 tokens average 2.0 per batch but about 1.02 per token. Switch formulas and the score halves; the model hasn't changed. The score is comparable only while prepare.py and the validation data match round 1's, so store their hash, check it before every score, and reject any kept edit that touches prepare.py.
  2. Is the gain bigger than the noise? A seed fixes the random starting weights and data order. Dodge et al. fine-tuned BERT, a pretrained language model, hundreds of times, changing only the seed. On RTE, a small test of whether one sentence follows from another, the best seed scored 77.3 on validation, against published BERT runs of 70.0 and 70.4. So run the starting code and the winner several times each; if their scores overlap, Day 35's tie rule applies.
  3. Does it hold on data the loop never saw? Cawley and Talbot found that overfitting the selection score is “often of comparable magnitude to differences in performance between learning algorithms”. The honest number comes from rows that never voted: a test split, looked at once, at the end. Autoresearch's prepare.py defines only training and validation splits, so you'd add one.
  4. Does it hold at full length? The README says the fixed budget means it “will find the most optimal model for your platform in that time budget”. The post's point follows: a short race favours whatever learns fastest early, which needn't win a run of days. So the costly last check: train the winner and the starting code for the real length and compare.

Worked example, with real numbers. Dwork et al. built data where the labels were coin flips, with 10,000 random features, 10,000 training rows and as many held-out rows, so no classifier can beat 50%. Picking the features most linked to the label, checked against a reused held-out set, then building a classifier from them, reported over 63% accuracy with 500 features, on both sets; in their plot, fresh data stayed at chance.

Where the premise outruns the evidence. Our reasoning: how much 100 rounds overfit depends on how big the validation set is. Recht et al. rebuilt the test sets of CIFAR-10 and ImageNet, two image-recognition benchmarks, which many papers had reused for almost a decade: benchmarks, not a 100-round loop. Accuracy dropped 3–15% and 11–14%, but the models kept their order, and the authors blame harder new images, not adaptivity. Autoresearch scores on 21 million tokens from one pinned shard. Our guess is that its selection overfit is small, but only a fresh test set can say.

6Follow-ups they'll ask

Why not use cross-validation inside the loop instead?

It makes each score less noisy, but the loop still chooses by those scores. Dwork et al. note that neither cross-validation nor the bootstrap (rescoring on resampled copies of the data) fixes overfitting to the held-out set in their coin-flip experiment. You still need a test set used once.

How would you redesign the overnight loop?

First, guard the scorer: before every score, the loop compares the scoring code and the validation data with a hash stored at round 1 and halts on a mismatch, so an edit to the loss-averaging formula can't quietly change the score. The keep bar becomes the baseline's seed spread, not zero. Every 20 rounds or so (our choice) the best gets a full-length run, and the night closes with a single test-split score.

The winner's test score is worse than its validation score. Was the night wasted?

Not necessarily: some drop is expected after selecting on validation. Compare the winner with the starting baseline on that test set. If it still wins by more than seed noise, the gain is real, just smaller (our reasoning).

7Check yourself

Why does a keep-only-if-better tuning loop always show a falling kept score?

An edit is kept only when it beats the best score so far; otherwise it is undone. So the kept score can only stay level or fall, whatever the edits really did.

In Dwork et al.'s coin-flip experiment, what did the reused held-out set report, and what was the true accuracy?

Over 63% with 500 selected features, on both training and holdout data. The true accuracy was 50%, because the labels were random.

Name four checks before trusting the winner of an overnight agent tuning loop.

The scoring code and data are untouched; the gain beats seed-to-seed noise; it holds on a test set scored once; it holds when retrained at the full training length.
