The pipeline that beat the agent

Original: AI Agent Engineering Interview #20 · The Agent Loop Trap

1The question

“A simple fixed pipeline (first find the buggy file, then write a patch, with no loop and no checking step) outscores your full coding agent on SWE-bench. So are agent loops not worth building?” Senior AI Engineer interview, Google

SWE-bench is a test set of real bugs taken from GitHub issues in popular Python projects. A fix counts only if the project's own tests pass afterwards.

2The trap

Trap A: “Agent loops are just hype. A plain fixed pipeline did better, so use that and skip the loop.”

Trap B: “The benchmark is wrong. On real work the agent would win.”

Both answers pick a side before asking why the pipeline won. The interviewer wants to see you find the cause.

3Your 30-second answer

“Not on its own. The difference between a pipeline and an agent is who picks the next step: my code, or the model. A loop only pays off if the model picks well at every step, because mistakes add up. At 95% per step, a 20-step run goes fully right only about a third of the time.

So when a pipeline wins, I check three things before I drop the loop: the task (SWE-bench Lite bugs are small one-file fixes, which suit a fixed route), the harness (are the tools and their feedback good?) and the model (was it trained to work in loops?). With the same model, the Agentless pipeline and a minimal two-tool agent scored almost the same on SWE-bench Verified, about 51% and 49%. So the loop wasn't the problem. I'd use a pipeline when I know the steps, and a loop when I don't.”

4The idea in plain words

You're driving to a friend's new flat. There are two ways to get there.

Written directions: “Take exit 3, second left, building 12.” This is fast and cheap, and it works perfectly when the directions are right. But if a road is closed you're stuck, because a piece of paper can't notice the roadblock.

Calling your friend at every junction: “I'm at the petrol pump, where now?” It's slower and costs more, but you can recover from a wrong turn. Every call is a chance to fix a mistake. It's also a chance to make one, if your friend mishears you.

The written directions are a pipeline (also called a workflow): the steps are fixed in code ahead of time. Calling your friend is an agent loop: the model looks at the task, chooses an action (open a file, run the tests), sees the result, and chooses again until it decides it's done.

Pipeline: your code picks each step
Find the file→Write a patch→Done
Agent loop: the model picks each step
Think→Act (call a tool)→See the result↺ repeat until done
Think about it. Your friend gets each junction right 95% of the time, and the trip has 20 junctions. How often do you arrive without a wrong turn? Multiply 0.95 by itself 20 times and you get about 36%. More steps means more chances to slip. That's why the checking step matters so much: running the tests is what turns those extra steps into a gain instead of a cost.

5How it works: what to check when a pipeline wins

  1. Does the task fit a fixed route? SWE-bench Lite keeps only bugs whose real fix edits one file in at most three places. “Find the file, then fix it” suits that well. A messy bug spread across many files needs exploring.
  2. Is the harness good? The harness is the code around the model: its tools, what they return, and the prompts. The SWE-agent paper showed that the tool design alone changes results a lot, for example a file viewer that shows 100 lines at a time, or an editor that rejects a broken edit.
  3. Is the model good at loops? A model trained on step-by-step tool use stays on track. An older model wanders and burns its steps.
  4. Is the comparison fair? Use the same model, the same budget and the same test set. Then read the runs to see where they failed.
  5. Decide per task. Use a pipeline when the steps are known and a loop when they aren't, or mix them: a pipeline with a test step and one retry.

Worked example, with real numbers. In mid-2024 the Agentless pipeline (find, repair, then check the patch) solved 32% of SWE-bench Lite's 300 bugs, the best of any open-source tool then, at an average cost of $0.70. That's where “the pipeline beat the agent” comes from. By December 2024, Agentless with Claude 3.5 Sonnet reached 50.8% on SWE-bench Verified. In January 2025, Anthropic's minimal agent (a prompt plus a shell tool and an edit tool) reached 49% on the same set with the same model. So with the same model the two scores were almost equal. The early gap came from weaker models and tools, not from the loop itself.

6Follow-ups they'll ask

When would you choose the loop anyway?

When the steps can't be known in advance: you have to reproduce the bug first, the change touches many files, or test failures and error messages need reading. Also when the model is strong at using tools.

How would you make your agent beat the pipeline?

Add a checking step (reproduce the bug, then run the tests), improve the tools, cap the number of steps, and start the agent from the pipeline's “find the file” result instead of from scratch.

What does the loop cost you?

More tokens, more time and more ways to fail. Set a step limit and a spending limit, and compare cost per solved bug, not cost per run.

7Check yourself

In one sentence, what's the difference between a pipeline and an agent?

In a pipeline your code fixes the steps ahead of time. In an agent the model picks each next step itself, based on what it has seen so far.

Each step is right 90% of the time. Roughly how often does a 10-step run go fully right?

About 35%, because 0.9 multiplied by itself 10 times is about 0.35.

Name the three things you check before saying “loops aren't worth it”.

The task (does it fit a fixed route?), the harness (tools and feedback) and the model (is it trained for loops?). Then compare fairly: same model, same budget.

8Words to know

Agent loop
The model repeats think → act → see the result until it decides the task is done.
Pipeline (workflow)
A fixed sequence of model calls and tools, written in code ahead of time.
Tool call
The model asks your code to do something (read a file, run tests) and gets the result back.
Harness
Everything around the model: tools, prompts, and how results are fed back.
SWE-bench Lite / Verified
Lite: 300 smaller one-file bugs. Verified: 500 bugs that people checked can actually be solved.
