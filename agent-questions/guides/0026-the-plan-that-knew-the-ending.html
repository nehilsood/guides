Agent question 26 of 30 · Day 31 · about 10 minutes

The plan that knew the ending

Original: AI Agent Engineering Interview #25 · The Synthetic Planner Trap

1The question

“We'd like a separate planner model, fine-tuned for the job. The only data we have is raw logs of what our agents did, step by step; nobody ever wrote a plan down. How do you turn those logs into a training set, and what's the riskiest flaw in the obvious way to do it?” Senior AI Engineer interview, Google DeepMind

A planner reads a task and writes the steps before anything happens; an executor carries them out on the real screen. Each log is a trajectory, and fine-tuning trains a model to write what its examples wrote.

2The trap

Trap A: “Have a strong model read each whole log, write the plan it implies, and train on those plans as they stand.”

Trap B: “Without real plans it can't be done; pay people to write them.”

Both skip the real question: what could a planner possibly know at the moment it plans?

3Your 30-second answer

“I'd turn each successful log into a pair: the task and the first screen as input, a plan as the target, with a strong model writing the plan from the log. Plan-and-Act did this, mapping every plan step to the actions it covers.

The danger is that the plan writer has read the ending. Its plan holds facts only the run found out, like which contributor topped a list. The planner is trained to produce those facts from the task alone, so it likely learns to state guesses as knowledge and never learns a ‘find out first’ step. So I'd flag any plan word that first appears late in the log, rewrite it as a find-out step, and add replanning examples cut mid-run.”

4The idea in plain words

A football club wants to train young coaches to write match plans. It has no old plans, only recordings of matches it won, so an analyst watches each one and writes the plan “we must have had”.

One reads: “Attack down the left; their right back gets booked in minute 20.” Nobody knew about the booking before kick-off. A young coach trained on hundreds of these learns that a good plan names exactly what will happen, and for his next match he writes in a booking that never comes.

The honest plan says: “Test both full backs early; if one is booked, attack his side.” It has a step for finding things out, which the replay hid.

Writing a plan from the finished log is hindsight relabelling. Its risk is hindsight leakage, guide 18's leakage in a new form: the target carries information the model won't have when it must answer.

Think about it. One plan says “Open alice-dev's profile and follow her”; another, “Find the contributor with the most commits, then follow them”. Which could anyone write before opening the website?

5How it works: building the set without the leak

  1. The recipe exists. Plan-and-Act (Erdogan et al., ICML 2025) prompted a teacher model (a stronger model that writes training examples; here GPT-4o) to “reverse-engineer” a plan from each successful web-agent trajectory, saying which actions belong to which step. Plans written without the trajectory didn't match the real website. The full system reached 57.58% on WebArena-Lite, a test set of tasks on real-looking websites.
  2. The leak is in the setup. My reasoning: the planner's input is the task; its target was written with the whole log in view. Plan-and-Act's own example shows the gap: “The original plan did not know who the top contributor was”, so it could only say to identify that person. A plan writer who has read the log can name them.
  3. Why that's dangerous. Training a model to produce facts its input lacks teaches it to invent. For question answering, Gekhman et al. (EMNLP 2024) found that examples with facts new to the model, once learned, “linearly increase the model's tendency to hallucinate”. Applying that to plans is my reasoning.
  4. Success-only logs hide replanning. Plan-and-Act kept only runs a checking model judged successful. My reasoning: clean wins rarely show a plan changing course, yet with its best executor, adding replanning raised WebArena-Lite success from 43.63% to 53.94%.
  5. A usefulness filter won't catch it. EAGLET (Si et al., ACL 2026) drops synthetic plans that lower executor scores. My reasoning: a plan carrying the answer helps on its own task, so it passes.
  6. The fix, my suggestions. Flag any name, number or path in a plan that first appears after the opening screen, and rewrite it as a “find out” step. Add replanning pairs: cut the log at step k; the input is the task, the old plan and screens up to k, and the target is the revised plan, as Plan-and-Act's replanning data does.

Worked example, an illustration with a made-up log. Task: “Follow the top contributor of the repo.” The six-step log: open the repo, open Contributors, sort by commits, read “alice-dev, 412 commits” (step 4), open her profile, click Follow.

Hindsight: “Open alice-dev's profile. Click Follow.”2alice-dev (step 4): flagged
Leak-free: “Open Contributors. Find who has the most commits. Open their profile and follow.”3none

The hindsight plan looks smarter. Once someone new tops the list, a planner trained on such plans is likely to name the old leader.

6Follow-ups they'll ask

Why not have people write the plans?

Scale and cost. Plan-and-Act calls collecting plans by hand “costly and time-consuming”; it generated 15,000 synthetic examples with GPT-4o in under an hour, against “days or weeks” to collect as many trajectories. I'd still have people plan a small sample, to audit the synthetic plans for steps nobody could know in advance.

Isn't hindsight relabelling a standard, safe trick?

For instructions, yes. NNetNav (Murty et al., 2024) lets an agent explore websites, then labels each run with the instruction it fulfils; Llama-3.1-8B fine-tuned on 10,000 such demonstrations reached over 16% success on WebArena. My reasoning: an instruction is the input and the run really carries it out. A plan is the output, written before the run, so hindsight there leaks.

How would you tell whether a trained planner picked up the leak?

My suggestions: on held-out tasks, count plan steps naming specific things absent from the task and first screen. Then change the site (a new top contributor, a moved file) and rerun; a leaky planner writes the old facts confidently.

7Check yourself

What did Plan-and-Act ask its teacher model to do with each trajectory?

Read a successful web-agent trajectory and “reverse-engineer” a structured plan from it, saying which actions belong to which plan step. Plans written without the trajectory didn't match the real website.

Why does a plan written after the run leak, when an instruction written after the run is fine?

An instruction is the input, and the run really does what it says. A plan is the target the planner must write from the task and first screen alone, so facts found mid-run (a name, a file) teach it to invent them.

In Plan-and-Act's table that adds one piece at a time, what did replanning add on WebArena-Lite?

With the fine-tuned executor and synthetic trajectories, success on these web tasks rose from 43.63% to 53.94%, a 10.31-point gain, the largest step for that executor.
