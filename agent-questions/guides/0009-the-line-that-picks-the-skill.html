The line that picks the skill

Original: AI Agent Engineering Interview #4 · The Skill Trigger Trap

1The question

“Your agent skips a skill that would clearly help. Then, on tasks that have nothing to do with it, it opens a skill that doesn't fit. Which is it: the prompt, the model or your evals? And how would you track it down?” Senior AI Engineer interview, Google DeepMind

A skill is a folder of instructions an agent can open when a task needs it. The agent always sees each skill's name and one short description. It reads the full instructions file, SKILL.md, only when it decides the skill applies. Loading in stages like this is called progressive disclosure.

2The trap

Trap A: “The skill's instructions are unclear. Rewrite them.”

Trap B: “The model is bad at choosing. Use a bigger one.”

Trap A edits the wrong text: the agent reads SKILL.md only after it has decided to open the skill, so the body can't change that decision. Trap B guesses without measuring. Neither looks at the one line that does the choosing.

3Your 30-second answer

“It's a routing problem, and only a test can show it. The agent opens a skill based on its short description alone, so that line is really a yes-or-no filter. Skipping a useful skill is a miss. Opening one on unrelated work is a false alarm. First I'd check the skill is listed at all. Then I'd write prompts that should and shouldn't trigger it, including close calls, measure both errors, rewrite the description to say what it does and when, and re-test on prompts I kept back.”

4The idea in plain words

Picture the receptionist in a big office building. Beside her is a board listing every department with a one-line label. Visitors say what they need, and she sends them on. She never reads a department's manual. She routes by the label alone.

One department's label says “Accounts”. People who can't log in to their account get sent there by mistake. People with an invoice question never get sent there, because the label doesn't mention invoices. Rewriting the department's manual fixes neither problem. Only the label decides where people go.

A skill's description is that label. A decision made from a short piece of text, yes or no, is a classifier, and a classifier makes two kinds of mistakes. A miss: the skill should have fired and didn't. A false alarm: it fired and shouldn't have. Two numbers track them. Recall asks: of the times it should fire, how often does it? Precision asks: of the times it fires, how often was it right to?

What the agent sees when it decides
User's request→Skill names + descriptions→Open a skill, or none
What it reads only afterwards
Skill chosen→Read SKILL.md→Follow the instructions
Think about it. To stop the misses, you widen the description: “Use for anything involving documents.” What happens to the false alarms? They go up, because now a request to rename a file can match too. Widening a description often trades one error for the other. That's why you measure both, not just the one someone complained about.

5How it works: debugging a trigger

  1. Check it's on the menu. In Claude Code, ask “What skills are available?”. If the header at the top of SKILL.md, where the name and description live, doesn't parse, Claude can't match against the description. And with many skills installed, Claude Code drops some descriptions to fit a budget (1% of the context window at the time of writing), starting with the least-used. A “miss” may be a skill the model never saw described.
  2. Write a trigger test set. Anthropic's skill-creator skill suggests 20 realistic prompts, 8–10 that should trigger and 8–10 that shouldn't. The most useful negatives are near-misses: prompts that share words with the skill but need something else. Run each prompt 3 times, since the choice varies.
  3. Score both errors and read the failing prompts. Misses and false alarms need opposite fixes.
  4. Rewrite the description. Anthropic's docs say it must cover what the skill does and when to use it, in the words users actually say, written in the third person. For misses, skill-creator notes Claude tends to under-trigger skills and suggests a slightly “pushy” description. For false alarms, Claude Code's docs say to make it more specific.
  5. Test on prompts you kept back. skill-creator splits the set 60/40 and picks the winning description by its score on the held-back 40%, so you don't just tune to the prompts you've seen.

Worked example. An illustration, put together from Anthropic's docs, with my own numbers. A skill's description is “Helps with documents”, which the docs list as too vague. Ten should and ten shouldn't prompts, each run 3 times, give 30 runs of each kind. The fix is the docs' own example: “Extract text and tables from PDF files, fill forms, merge documents. Use when working with PDF files or when the user mentions PDFs, forms, or document extraction.”

DescriptionFired on “should” runsFired on “shouldn't” runsRecallPrecision
“Helps with documents”12 of 309 of 3040%12 ÷ 21 = 57%
The specific one27 of 302 of 3090%27 ÷ 29 = 93%

Then run the kept-back prompts. If they score about the same, the fix holds beyond the prompts you tuned on.

6Follow-ups they'll ask

So when is it really the model?

Partly on simple tasks: skill-creator says Claude consults skills only for tasks it can't easily handle itself, so a one-step request may never trigger one. Also when the same test set passes on one model and fails on another. Test with the model your users run.

Is a false alarm worse than a miss?

Often. A miss loses some help. A false alarm puts instructions that don't fit into the agent's context, and it may follow them. For a skill with side effects, like deploying, Claude Code lets you set disable-model-invocation: true so only a person can start it.

How do you stop it breaking again?

Keep the test set and rerun it whenever a description changes or a new skill arrives. A new skill with a similar description can start taking another skill's triggers.

7Check yourself

Why doesn't rewriting the SKILL.md body fix a skill that fires at the wrong times?

The agent decides from the name and description alone. It reads the body only after it has chosen, so the body can't change the choice.

In plain words, what are recall and precision for a skill?

Recall: of the times it should fire, how often it does. Precision: of the times it fires, how often it was right to.

What is a near-miss prompt, and why is it the best negative test?

A prompt that shares words with the skill but needs something else. An obviously unrelated prompt tests nothing; a near-miss shows whether the description really separates the cases.

8Words to know

Skill
A folder of instructions (SKILL.md, plus optional files) an agent opens when a task needs it.
Progressive disclosure
Name and description always in view; the full instructions loaded only when chosen.
Recall / precision
How many of the right cases it catches / how many of its picks are right.
Near-miss
A test prompt that looks like a match but isn't.
