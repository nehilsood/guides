Agent question 6 of 30 · Day 11 · about 10 minutes

The summary that cost more

Original: AI Agent Engineering Interview #27 · The Context Compaction Trap

1The question

“In your coding agent, you replaced each raw tool output with a short summary written by a model. The prompts got much smaller. Yet the cost of each fixed issue stayed flat, and sometimes it rose. Where did the money go, and how would you show it from the traces?” Senior AI Engineer interview, Anthropic

A trace is the log of one run: every step the agent took, what it sent to the model, what came back, and the tokens billed.

2The trap

Trap A: “The summaries cost money to write. Use a cheaper model for them.”

Trap B: “Summarise even harder, so the prompt shrinks more.”

Trap A is true but small: in the study below, writing summaries was at most 7.2% of an issue's cost. Trap B makes the real leak worse. Both look at one step; the bill depends on the whole run.

3Your 30-second answer

“The cost of an issue is roughly the cost of one step times the number of steps. My first suspect is that I shrank the first and grew the second: when a summary drops a detail, like the exact error line, the agent runs the tool again. Second suspect: summaries that rewrite history break the prompt cache, so cheap cached tokens become full price.

The traces settle it: steps per issue, cached tokens per step, repeated tool calls. The usual fix is simpler: hide old outputs, keep the agent's own actions, and only ever add to the history.”

4The idea in plain words

You're cooking a new dish, and a friend reads the recipe to you over the phone. To save time, she gives you one-line versions: “Make the sauce.” Soon you're ringing back: “How much salt?” Shorter calls, more calls, no time saved.

That's this bug. In guide 1's loop, each tool result goes back into the model's context, and the whole history is sent again on every step. A summary makes each result smaller, but the agent loses details it didn't know it would need, so it runs more steps. The full path of one run is its trajectory; a longer trajectory can cost more even when every step is smaller.

A second picture: a copy shop has already copied the first 40 pages of your report, so copying them again is nearly free. Change page 3, and every page after it must be copied fresh. That's prompt caching: if a request begins with exactly the same text as the last one, those tokens cost much less. Rewrite something early and everything after it is full price.

Raw outputs: big steps, fewer of them
Run tests→Full log kept→Fix the line
Summaries: small steps, more of them
Run tests→“Auth tests failed”→Run tests again→Fix the line
Think about it. The agent ran the tests and got a 500-line log. The summary says “3 tests failed in the login module.” Three steps later it needs the exact error and line number. What does it do? It runs the tests again: one more step, with the whole history resent.

5How it works: finding the money in the traces

  1. Split the bill per issue. Number of steps, input tokens per step (cached and not), output tokens, and the summariser's own calls, since each summary is an extra model call.
  2. Compare step counts on the same issues, before and after.
  3. Count repeats. The same tool with the same arguments called twice in one run means a detail was lost.
  4. Check the cache. If the share of cached tokens per step fell after the change, the summaries are rewriting the start of the prompt.
  5. Fix it simply. Replace old outputs with a short placeholder but keep the agent's reasoning and actions, keep file paths and URLs so detail can be fetched again, and only add to the history, never edit it.

Worked example, with real numbers. JetBrains researchers (The Complexity Trap, 2025) ran SWE-agent on SWE-bench Verified (guide 1), comparing summaries with simply hiding old tool outputs, called observation masking. With Gemini 2.5 Flash, summarised runs averaged 52 turns against 44 with masking, about 18% more, and cost $0.24 per issue against $0.18. With Qwen3-Coder 480B, the paper reports summarised runs 15% longer than the raw agent's and 13% longer than masking's. Both methods cut the raw agent's $1.29 roughly in half, but masking was cheaper ($0.61 vs $0.64) and solved slightly more (54.8% vs 53.8%). The authors' guess at why runs grew: summaries may hide the signs of failure that would make the agent stop sooner.

Note what the study does not show: flat or rising cost. Against the raw agent, summaries still saved about half. What it shows is why summaries lose ground to simple masking. Whether your agent's flat cost comes from this is what your own traces must show.

Now the cache. Anthropic's prompt caching docs say, at the time of writing, that reading cached tokens costs 0.1 times the normal input price on most models, writing them costs 1.25 times, and a change anywhere invalidates everything after it. As an illustration from those numbers (not a measured run): a 50,000-token history read from cache costs about as much as 5,000 normal tokens; a 10,000-token summary rewritten every step, about 12,500. The smaller prompt is the dearer one. Anthropic's own computer-use demo skips trimming old screenshots when caching is on, for this reason.

6Follow-ups they'll ask

Isn't masking also throwing information away?

Yes, but the agent still sees what it did and why, so it knows the output existed and can rerun the tool. In the study, masking solved about as many issues as summarising, and cost less in the runs it measured.

So is summarising never right?

It helps when the history truly won't fit. Do it rarely and in batches (the study summarised 21 turns at once and kept the last 10 whole), and keep paths so details can come back.

Which number goes on the dashboard?

Cost per solved issue, the measure from guide 1's follow-ups, split into steps times cost per step, with the cached share beside it.

7Check yourself

Smaller prompts, same cost per issue. Where's the first place to look?

The number of steps per issue. A lost detail makes the agent run tools again, so runs get longer.

How can rewriting the history raise the price of each step?

It breaks the prompt cache. On most models, at the time of writing, cached tokens cost a tenth of the normal price, and a change early in the prompt makes everything after it full price again.

What does observation masking keep, and what does it drop?

It keeps the agent's reasoning and actions and drops the old tool outputs, putting a short placeholder in their place.

8Words to know

Trajectory
The full sequence of steps an agent takes on one task.
Prompt caching
The provider reuses the unchanged start of a prompt and bills those tokens at a lower price.
Observation masking
Replacing old tool outputs with a placeholder while keeping the agent's own reasoning and actions.
