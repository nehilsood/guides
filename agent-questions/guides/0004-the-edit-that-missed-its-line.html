The edit that missed its line

Original: AI Agent Engineering Interview #21 · The Unified Diff Trap

1The question

“A coding agent's only tool is a shell. It can search files, edit with sed and patch, and run the tests. Yet its file edits keep going wrong. Why, and what edit tool would you build in place of diffs that point at line numbers?” Senior AI Engineer interview, Google

A unified diff is the change format git diff prints: a header with line numbers such as @@ -2,4 +3,5 @@, then the lines, marked + for added and - for removed. sed is a command-line tool that edits text using a pattern typed into the command.

2The trap

Trap A: “A bigger model will get the edits right.”

Trap B: “Put more sed examples in the prompt.”

Both treat it as a skill problem. It's a tool problem: the edit format asks the model to do things it is bad at, and gives no feedback when it slips.

3Your 30-second answer

“Two things break edits in a shell. Line numbers go stale: every edit that adds or removes lines shifts everything below it, so the next diff points at the wrong code. And the code has to survive the shell: quotes and slashes inside a sed command need escaping, one slip changes the wrong thing or nothing, and sed doesn't show you what happened.

So I'd give the agent an edit tool that anchors on content: ‘replace this exact text with that text’. It applies only if the old text matches exactly once, and otherwise says why. It shows the edited lines back, and it rejects edits that break the syntax. The SWE-agent paper measured this: removing its edit command and syntax check dropped the agent from 18% to about 10% on SWE-bench Lite.”

4The idea in plain words

You're fixing a shared document with a colleague over the phone. You say: “Go to line 42 and change it to ‘Goodbye’.” But a minute ago you asked them to add three lines near the top. Line 42 is now a different sentence. They overwrite it, and neither of you notices.

Now try: “Find the sentence that says ‘Hello!’ and change it to ‘Goodbye!’.” It works wherever that sentence has moved. If ‘Hello!’ appears twice, your colleague asks “which one?” instead of guessing. If it isn't there, they say “not found”, and you know straight away.

The first way is a line-number edit. The second is a search-and-replace edit, anchored on content. There's a second problem too. Dictating code through sed is like reading punctuation aloud over the phone: “quote, backslash, slash…”. Every symbol is a chance to slip.

By line number
Edit 1 adds 3 lines→Edit 2: “change line 40”→Wrong line changed, no error
By content
Edit 1 adds 3 lines→Edit 2: “replace this text”→Right place, or a clear error
Think about it. The agent plans two edits at once. The first adds 3 lines at line 10. The second targets line 40. After the first runs, where is the code that used to be on line 40? On line 43. Line 40 now holds what used to be line 37, so the second edit lands three lines too high.

5How it works: an edit tool built for a model

The SWE-agent paper calls the tools an agent uses, and what they print back, its agent-computer interface (ACI). It's the part of guide 1's harness the model touches.

  1. Anchor on content. The tool takes the old text and the new text. In Anthropic's text editor tool the old text must match exactly, including spaces and indentation, and exactly once. Anthropic tried several edit styles for its SWE-bench agent and found this one the most reliable.
  2. Fail loudly and helpfully. No match: “No match found.” Several: “Found 3 matches… provide more context.” The model can fix that on the next step.
  3. Show the result. SWE-agent's authors call shell editing “silent”: checking that an edit worked takes extra commands. Print the changed lines back.
  4. Reject broken code. Run a linter (a quick syntax checker) and refuse any edit that adds a syntax error, showing what the file would have looked like.
  5. Keep code out of escaping. Pass old and new text as plain tool arguments, not inside a shell command.

Worked example, with real numbers. SWE-agent ran GPT-4 Turbo on SWE-bench Lite's 300 bugs and removed one piece of the edit tool at a time:

Edit setupBugs fixed
No edit command (sed, or rewrite the whole file)10.3%
Edit command, no syntax check15.0%
Edit command with syntax check18.0%

Failed edits snowball. Any edit attempt had a 90.5% chance of eventually succeeding; after one failed attempt, that fell to 57.2%. Among the bugs the agent didn't fix, cascading failed edits made up 23.4% of the failures.

6Follow-ups they'll ask

SWE-agent's edit command uses line numbers. Why did it work?

Its file viewer printed fresh line numbers next to the code and showed the file again after each edit, so the numbers were never stale. Line numbers fail when they're out of date or the model has to work them out.

So are diffs always wrong?

No. Aider found GPT-4 Turbo did better with a simplified diff than with its search/replace blocks (61% vs 20% on 89 refactoring tasks), but that diff had its line numbers dropped, and each change was applied by matching its content. The lesson is “anchor on content”, whatever the format.

What if the old text appears twice?

The tool refuses and asks for a few more surrounding lines to make the match unique. Guessing would edit the wrong place silently.

7Check yourself

Why do line numbers in a second edit go wrong?

The first edit added or removed lines, so everything below it moved. The old numbers now point at different code.

What should a content-anchored edit do if the old text matches nowhere, or in two places?

Change nothing and return a clear error: “not found”, or “several matches, add more context”.

In SWE-agent's test, what happened without a proper edit command?

The agent fixed 10.3% of SWE-bench Lite instead of 18.0%, with the same model.

8Words to know

Unified diff
The git diff change format: line-number headers, then lines marked + and −.
Search-and-replace edit
An edit that finds an exact piece of old text and swaps in new text, with no line numbers.
Linter
A quick checker that spots syntax errors without running the code.
Agent-computer interface (ACI)
The tools an agent uses and what they print back.
