Agent question 7 of 30 · Day 12 · about 10 minutes

The step it did twice

Original: AI Agent Engineering Interview #15 · The Pixel-Memory Paradox

1The question

“Our agent works a computer screen. It keeps every screenshot and every action in its context. Web tasks of about 15 steps go well. On a 300-step desktop job, from roughly step 80 it begins doing things it has already done. The team's plan is to move to a model with a 2-million-token window. Why won't that help?” Senior AI Engineer interview, Google DeepMind

A computer-use agent runs guide 1's loop on a screen: it looks at a screenshot, chooses a click or a keystroke, then gets a new screenshot. Its context window is how much text and images the model can take in at once.

2The trap

Trap A: “A bigger window holds the whole run, so it can't forget.”

Trap B: “Shrink the screenshots so more of them fit.”

Both assume the problem is room. But the trouble starts at step 80, when the screenshots would fill only a small part of a 2M window (see the table below). The problem is finding the right fact, not storing it.

3Your 30-second answer

“Window size is storage, and this is a finding problem. By step 80 the context holds 80 near-identical screenshots, and none of them says which steps are done. Models get worse at using a long context, especially one full of look-alikes. A 2-million-token window just holds more of them.

So I'd give memory a structure: a written progress log the agent updates every step, only the last few screenshots, and a check after each action. Then ‘invoice 57: done’ is a line to read, not pixels to compare.”

4The idea in plain words

You're entering 300 invoices into a system at your desk. After each one, a colleague takes a photo of your screen and drops it in a box. To decide what to do next, you flip through the box.

For the first 15 photos, this works. By photo 80, every photo shows the same screen with slightly different numbers. Did you enter invoice 57? You'd have to find the right photo and spot a tiny difference. So you guess, and sometimes you enter it again.

A bigger box wouldn't help. A checklist would.

The box is the model's context window. The trouble you had flipping through it has a name, context rot: as the context grows, the model gets worse at recalling what's in it. The photos that look almost the same are distractors: material similar to the right answer but wrong. The checklist is structured note-taking: the agent writes its progress to a file outside the window and reads it back.

Memory as a pile of screenshots
80 look-alike screenshots→“Did I do step 57?”→Guess, maybe repeat
Memory as a log plus a few screenshots
Progress log + last 3 screenshots→“57: done”→Go to step 58
Think about it. Two screenshots of a spreadsheet, before and after the agent typed into cell B7, differ by a few pixels. Which tells the agent more reliably that B7 is done: those two images buried among 80 others, or one line in a list saying “B7 filled”? Pixels show what the screen looked like. They don't say what's finished.

5How it works: memory in parts

  1. A plan and a progress log. The agent keeps a file with the goal, the steps, and which are done, and updates it after each step. Anthropic describes this as structured note-taking, like a NOTES.md file. Their Pokémon-playing agent kept notes such as how many levels a character had gained toward a target.
  2. Only recent screenshots. Anthropic's computer-use docs suggest keeping the last three screenshots and removing old ones in batches, every 25 turns, so the prompt cache from guide 6 keeps working between removals. For the newest models they suggest clearing old screenshots on the server side instead.
  3. Check after each action. The same docs warn that the model sometimes acts as if an action worked without checking, and suggest a prompt: after each step, take a screenshot and say whether it succeeded.
  4. Write facts, not pictures. Log what happened in words: “clicked Submit on invoice 57, confirmation shown.”
  5. Compact when it gets long. Summarise older history when needed, but keep the log whole, since it is the agent's real memory.

Worked example, with real numbers. Anthropic's computer-use docs put one screenshot at roughly 1,000–1,800 input tokens. As an illustration built from that range (screenshots only, the real sizes depend on the screen):

So a 2M window could hold even the whole 300-step run. Holding it was never the hard part; using it is. Lost in the Middle (Liu et al., 2023) found models use information best when it sits at the start or end of the input, and much worse in the middle, even models built for long inputs. Chroma's Context Rot report (Jul 2025) tested 18 models and found performance changes with input length even on simple tasks, and that distractors hurt more as the input grows. Eighty near-identical screenshots are exactly that case.

6Follow-ups they'll ask

Why keep three screenshots, not just the latest one?

The docs don't say why. A likely reason: to check that an action worked, the agent compares the screen before and after it, and one screenshot can't show a change.

What goes in the progress log?

The goal, the list of steps with done or not done, the last state the agent confirmed, and any values it has typed, such as ids or totals.

How would you show the fix worked?

Rerun the 300-step job and count repeated actions: the same action on the same item twice. Compare that count, and the success rate, before and after.

7Check yourself

Why won't a 2-million-token window fix the repeats?

Room isn't the problem. The agent has to find which steps are done among many look-alike screenshots, models get worse at that as the context grows, and a bigger window only adds more of them.

What is context rot?

As the context grows, the model gets worse at recalling and using what's in it, especially when similar-looking distractors are present.

Name three parts of a better memory for this agent.

A written progress log it updates every step, only the last few screenshots in context, and a check after each action that it worked.

8Words to know

Computer-use agent
An agent that works a screen: screenshot in, click or keystroke out.
Context rot
The model's recall getting worse as its context grows.
Distractor
Material that looks like the right answer but isn't.
Structured note-taking
The agent writes its progress to a file outside the context and reads it back.
