The habit that came back

Original: AI Agent Engineering Interview #14 · The Language Prior Trap

1The question

“A user has your coding agent move a big data-processing pipeline from Python to Rust, and the result is excellent. But on every task after that, it switches back to Python, writing it and running it. Is the prompt the problem?” Senior AI Engineer interview, GitHub

Moving code from one language to another is called a port. Rust is a fast, compiled language; its build tool is cargo, and cargo test runs a Rust project's tests.

2The trap

Trap A: “Write the instruction more clearly: ALWAYS use Rust.”

Trap B: “The model just can't do Rust.”

The user did ask clearly, and it worked once. The port proves the model can write Rust. What's missing is something that holds the choice after the request goes quiet.

3Your 30-second answer

“Not really. The request is one sentence in one turn. Against it stands the model's habit: models reach for Python even where it's a poor fit, likely because the code and practice tasks they learn from are Python-heavy. And they forget earlier instructions as a conversation goes on. So the sentence wins once, then fades. I'd make the project itself say Rust: the rule in its instructions file, the old Python archived, and a check that keeps Python files out and passes only when cargo test does.”

4The idea in plain words

Your family moves the mugs from the right-hand cupboard to the left one. Someone tells you once. The next morning you get it right, because you've just heard it. A week later, half asleep, your hand goes straight to the right-hand cupboard. Years of habit beat one sentence.

What would actually fix it? A note on the old cupboard door helps, though after a while you stop seeing notes. Emptying the old cupboard works better: your hand finds nothing there. A lock on it works best, because then it doesn't matter what you remember.

The model has a habit too. Researchers call it a prior: what the model leans towards before it reads your request. For coding, the prior says Python. The user's sentence is the one-time reminder. The rest of this guide is about the note, the empty cupboard and the lock.

The rule lives in one chat message
“Use Rust” (turn 1)→Port done in Rust→Next task: back to Python
The rule lives in the project
Rule file + Rust-only repo→Python run blocked→Done only when cargo test passes
Think about it. The port went perfectly. Why does that tell you little about the next task? The port had the Python original to copy and a fresh request; the next task has neither. Only one of those is about the prompt.

5How it works: moving the rule out of the chat

  1. Find where the rule lives. If it's only in a chat message, it gets older with every turn. The Multi-IF study found that as turns go by, models increasingly forget instructions they had followed in earlier turns.
  2. Put it where every session reads it. Claude Code loads its project instructions file (CLAUDE.md, or a repo's AGENTS.md) at the start of every conversation. That's the note on the door. Its docs are honest about the limit: “Claude treats them as context, not enforced configuration.”
  3. Make the repo agree. Archive the old Python pipeline. If a search of the project finds working Python, the project argues for Python.
  4. Block what must never happen. The same docs say: “To block an action regardless of what Claude decides, use a PreToolUse hook instead.” A hook is your script that runs before the tool calls you choose. If it exits with code 2, the call is blocked and the script's message goes back to the model as the tool's error: “This project is Rust. Use cargo.” That's the lock.
  5. Judge the result. A task counts as done only when cargo test passes. A check doesn't have to be remembered to work.

Worked example, with real numbers. First, the prior itself can be measured. Twist et al. (2025) asked eight models, including GPT-4o-mini, Claude 3.5 Sonnet and Qwen-2.5-Coder, to start five projects where Python is a weaker fit, such as a low-latency trading platform, 100 times each. Python was the most-used language in 23 of the 40 model-and-project pairs (58%), and Rust was not used once.

Where it comes from is harder to see, since we can't inspect these models' training data. Two likely sources are the code models learn from and the practice tasks coding agents train and are tested on, and the public training sets and benchmarks we can see lean heavily on Python. SWE-Gym, the first training environment for such agents by its authors' account, holds 2,438 tasks, all in Python. The Multi-SWE-bench authors note that existing benchmarks such as SWE-bench (guide 1) focus almost entirely on Python.

And the fading: Multi-IF tested 14 models on three-turn conversations, and every one followed instructions less well with each extra turn. o1-preview fell from 0.877 at turn 1 to 0.707 at turn 3. No study measured this exact relapse, but together these findings explain it.

6Follow-ups they'll ask

Why not repeat “use Rust” in every turn?

It's still a request the model weighs against its habit, paid for on every turn. A check works whether the model remembers or not.

Should every Python run fail?

Only Python that would ship. A throwaway script to compare two outputs is the agent thinking with a tool. Block Python files landing in the project, and let cargo test decide when the task is done.

Isn't the real fix retraining the model?

Longer term, maybe: Twist et al. call for targeted fine-tuning and more varied training data. But you don't control that. You do control the repo, the hooks and the tests, today.

7Check yourself

Why doesn't one perfect port prove the agent will keep using Rust?

During the port it had the Python original to copy and a fresh request. Later tasks have neither, and the model's Python prior is still there.

Name two likely sources of the Python prior.

The code models learn from, and the practice tasks coding agents train and are tested on. A model's training data isn't public, but the public training sets and benchmarks we can see are mostly Python.

Put these in order from weakest to strongest: a hook that blocks Python, a chat message, the project instructions file.

Chat message, then instructions file, then hook. The first two are context the model weighs and can forget. The hook acts whatever the model decides.

8Words to know

Port
Moving a program from one language to another.
Prior
What a model leans towards before it reads your request, learned in training.
Hook
Your own script that runs at a set point, such as before every tool call, and can block it.
cargo test
The command that runs a Rust project's tests.
